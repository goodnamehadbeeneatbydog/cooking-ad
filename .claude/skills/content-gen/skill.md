# Content-Gen（内容站文章生成器）

## 快速开始

### 方式一：指定主题生成
```
用户: content-gen 写一篇关于AI代码助手工具的文章
系统: 生成文章 → De-AI处理 → 自动分类 → 保存MD → 返回文件路径
```

### 方式二：批量生成
```
用户: content-gen --batch 5 --category "AI工具"
系统: 生成5篇AI工具类文章 → 批量De-AI → 保存 → 返回列表
```

### 方式三：自动部署
```
用户: content-gen --deploy 写一篇关于效率工具的文章
系统: 生成文章 → De-AI → 保存 → 构建 → 推送GitHub → Vercel自动部署
```

## Workflow

### Step 1: 主题分析与大纲生成

**输入**: 用户提供的主题/关键词

**输出**: 文章大纲
```yaml
outline:
  title: "文章标题"
  description: "SEO描述（120字以内）"
  keywords: ["关键词1", "关键词2"]
  structure:
    - heading: "引言"
      points: ["要点1", "要点2"]
    - heading: "主体部分1"
      points: ["要点1", "要点2"]
    - heading: "主体部分2"
      points: ["要点1", "要点2"]
    - heading: "总结"
      points: ["要点1"]
```

### Step 2: 文章生成

**写作规范**:
- 语言: 根据用户要求（中文/英文）
- 字数: 1500-3000字
- 风格: 工具评测/教程/推荐清单
- 必须包含: 工具介绍、使用场景、优缺点、替代方案

**文章结构模板**:
```markdown
## 引言（100-200字）
- 痛点引入
- 文章价值承诺

## 工具介绍（每工具200-400字）
- 工具名称 + 一句话描述
- 核心功能
- 使用场景
- 优缺点

## 对比总结
- 表格对比
- 推荐场景

## 结语
- 核心观点重申
- 行动号召
```

### Step 3: De-AI处理（核心步骤）⭐

**3.1 24种AI模式检测清单**

| 类别 | 检测模式 | 修复方法 |
|------|---------|---------|
| 内容 | 过度强调重要性 | 删"至关重要的/革命性的/颠覆性的" |
| | -ing假装深度 | 删"symbolizing/highlighting/redefining" |
| | 促销语言 | 删"stunning/breathtaking/game-changing" |
| | 空泛总结 | 每个观点必须有具体例子支撑 |
| 语言 | AI高频词 | 替换 Additionally→而且, crucial→关键, delve→深入 |
| | 系动词回避 | "serves as"→"是", "acts as"→"作为" |
| | 否定平行 | 删"Not only...but also..." |
| | 连接词堆砌 | 减少"Furthermore/Moreover/Consequently" |
| 风格 | 破折号过度 | →改用逗号或句号 |
| | 粗体过度 | 删除机械强调 |
| | 列表泛滥 | 减少无意义bullet point |
| | 段落长度一致 | 长短句交替，打破规律 |
| 结构 | 完美对称 | 故意打破对称结构 |
| | 三段式模板 | 避免"首先/其次/最后"的机械结构 |
| | 过度过渡 | 删除冗余的过渡句 |
| 表达 | "值得注意的是" | →直接说内容 |
| | "不难发现" | →删除，直接呈现 |
| | "众所周知" | →删除或用具体数据替代 |
| | "笔者/本文" | →改用"我/这篇文章" |
| 个性 | 无个人见解 | 添加个人使用体验和真实感受 |
| | 无情感温度 | 加入吐槽、惊喜、困惑等真实情绪 |
| | 完美中立 | 表达明确的偏好和立场 |
| | 过度专业 | 适当加入口语化表达 |

**3.2 添加灵魂六法则**

1. **有意见** - 不只是罗列功能，要表达真实评价
   - ❌ "这款工具提供了多种功能"
   - ✅ "我用了三个月，发现它的自动保存功能救了我至少三次"

2. **变化节奏** - 短句+长句交替
   - ❌ 连续三个长句
   - ✅ "爽。这个功能直接让我抛弃了之前的工具。虽然界面丑了点，但谁在乎呢？"

3. **承认复杂性** - 表达混合感受
   - ❌ "这是一款完美的工具"
   - ✅ "功能强大，但学习曲线陡峭。适合有耐心的人。"

4. **使用"我"** - 第一人称更真实
   - ❌ "用户可以使用该功能"
   - ✅ "我用这个功能的时候，第一反应是..."

5. **让混乱进来** - 允许离题、旁白
   - 加入使用过程中的意外发现
   - 提到无关但有趣的细节

6. **具体感受** - "令人印象深刻"→"凌晨2点还在用它赶进度"

**3.3 工具类文章特化去AI**

- **真实使用场景**: 不是"适用于团队协作"，而是"我们5人小组用它管理了3个月的项目"
- **具体版本号**: 提到测试时的具体版本
- **真实痛点**: "之前用XX工具，每次导出都要等30秒，这个工具3秒搞定"
- **不完美评价**: "功能很强，但文档写得太烂，我花了两天才搞懂配置"
- **价格敏感**: "免费版够个人用，但团队版每月$20有点小贵"

**3.4 最终审计问答**

> Q: "这段文字哪里看起来像AI写的？"
> A: 列出3-5个可疑痕迹
>
> Q: "怎么改才能不像AI？"
> → 最终修订版

## Critical Rules

1. ✅ **De-AI是必须的** - 每篇文章必须经过24模式检测和灵魂六法则处理
2. ✅ **真实体验** - 文章必须包含虚构但合理的个人使用体验
3. ✅ **具体细节** - 避免空泛描述，必须有具体功能、版本、场景
4. ✅ **自动分类** - 必须根据内容自动匹配分类，不能全部归为"未分类"
5. ✅ **SEO友好** - title必须包含关键词，description在120字以内
6. ✅ **长度控制** - 1500-3000字，不能太短也不能太长
7. ✅ **多平台适配** - 生成后检查是否适合AdSense广告插入（段落数>5）
8. ✅ **去AI化检查** - 最终输出前自检："如果我是读者，会觉得这是AI写的吗？"
